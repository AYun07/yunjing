一、为什么你说"修好了却看不到"——两个真根因

根因 A · 存档每次启动都"消失"

客户端内置服务器用 server.listen(0)，即每次启动随机端口。浏览器 localStorage 是按协议+域名+端口隔离的，端口一变，旧存档就落在另一个 origin 下、读不到。

已修：改为固定端口 18760 并写入 userData 记住；端口被占用则向后找并记住最终值。配合已有的单实例锁，同一个用户每次都落到同一 origin。

根因 B · 界面/公告永远停在旧版

内容更新有多个 CDN 源，实测 cdn.jsdelivr.net 已到 7.0.2、fastly.jsdelivr.net 还停在 7.0.1。旧逻辑"第一个源成功就用"，若先命中缓存滞后的源，就误判"已是最新"，不再拉新文件——于是工坊/设置/公告都停在旧界面。

已修：遍历全部源、取版本号最高的清单。端到端模拟"旧源在前、新源在后"验证：正确识别到 7.0.3 并下载新文件。

四、需要如实说明的两件事

① 存档修复在"程序壳"里，这一次仍需重装一次

固定端口的改动在 Electron 主进程（app.asar），属于程序壳。内容热更新改不到壳，所以这一次需要装一次 v7.0.3 安装包，把修好的壳装上去。

装完 v7.0.3 之后，后续的内容/界面/公告修复都能自动热更新，不用再重装。这是最后一次性重装，原因是这次修的正是"存档隔离"这个壳层根因本身。

② 发版上传还差一个 GitHub 令牌

当前环境没有可用的 GitHub 凭证（gh auth status 显示未登录）。代码、清单、基线、公告都已就绪并验过三源一致，但把 v7.0.3 安装包发布到 Release、把清单推到 CDN 这一步需要你再提供一次令牌。我不会编造一个假的成功发布。
