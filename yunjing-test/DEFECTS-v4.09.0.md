## 【I 组 · 能力边界攻坚】（对应 v4.08.0 第七节 1/2/3/5）

### I-1　小模型自编经济 / 面板数值 —— 从「能力边界」改为「确定性兜底」

- **现象（v4.08.0 H-1）**：`agnes-3.0-flash` 长叙事里偶发自编「木剑才卖 5 金币」
  「剩下 20 金币」「经验 +10000」「声望 +50」「HP 346/470」「怒气 72/106」
  「总金币 99」「目前 1/1」「背包 1/1」。
- **v4.08.0 的处置**：提示词 4.1~4.4 压制 + 判定器如实检出 + 清洗层剥离确定性 UI 块，
  但零散句式变体挡不住，只能登记为能力边界。
- **v4.09.0 修法**：新建 `js/number-scrubber.js`，接入 `js/ai-response-handler.js` 清洗链末尾。
  - **A 类 · 面板字段片段**：`HP x/y` / `总金币 N` / `怒气 x/y` / `余额 N` 等一律剥离
    （结算信息本就由 UI 卡片呈现，不该进正文），连前导连接标点一起吃，避免留下「，。」。
  - **B 类 · 结算增量**：`经验 +N` / `声望 +N` / `攻击 +N` 改成中性叙述
    （「经验略有增长」「声名渐起」「攻势更盛」），数字无论真假都不写进正文。
  - **C 类 · 货币 / 资源数量**：按**金币真值白名单**判定，合法数字保留，非法数字改写为
    「些许金币」。白名单只收余额 / 流水 / 委托报酬 / 历史余额，**不收 HP / 等级 / 点数**。
  - **D 类 · UI 进度对**：背包格数与模糊前缀的 `N/M` 一律剥离；明确的进度 / 阶段前缀
    查 `legalPairs`（委托 cur/need、经验条、血条、蓝条、世界阶段）。
  - **降级**：拿不到 `TruthSnapshot` 时只做 A/B/D 剥离，不改写数量，避免误伤合法数字。
  - **零误伤口径**：只匹配阿拉伯数字 + 明确字段 / 货币上下文；中文数字
    （「三十金币」「三日后」「第五层」）完全不在受管范围。
- **自检暴露并修掉的两个真漏洞（都是"换壳绕过"同型）**：
  1. `activeQuests` 里存在合法 `1/1` 委托进度对 → 「背包 1/1」「目前 1/1」被冒用放行。
     修法：按前缀分类，背包 / 模糊前缀一律视为 UI 残骸，不查全局进度对集合。
  2. 初版把 `nums` 里**所有字段**的数字收进白名单 → 真实快照下 `points:5` / `round:5`
     让编造的「木剑才卖 5 金币」蒙混过关（浏览器真实快照探针实测）。
     修法：拆出 `legalMoney()`，只认金币真值。
- **验证**：
  - `yunjing-test/scripts/t_number_scrub.js`：23 条正反样本全通过；
    4 个变异体（禁用面板剥离 / 增量改写 / 货币改写 / 进度剥离）**4/4 被检出**。
  - 浏览器真实快照端到端探针：模块加载正常、零 pageerror；
    `总金币 99` → 剥离、`HP 346/470` → 剥离、`经验 +10000` → 中性叙述、
    `5 金币` → `些许金币`、`目前 1/1` → 剥离；中文数字与合法数值零误伤。
  - `studio.html` 加载顺序、`sw.js` CORE2 预缓存清单同步补齐（防 PWA 离线 404）。
- **状态**：已修复并验证。**玩家看到的正文里不再可能出现引擎真值之外的经济 / 面板数值。**

### J-1　模型只吐思维链 → 玩家看到空白卡片（确定性产品缺陷，已修）

- **现象**：`doupocangqiong / act2` 报 `{"empty": true}`。原始返回是 1677 字节的**整块
  英文思维链** `(Thinking process: 1. Analyze the Request: …)`，一个中文叙事字都没有。
- **根因**：`v4.08.0` 的 `_stripThinkingChain` 把思维链全剥掉后 `out` 为空，
  `_rescueProse` 也救不回（英文推理段 CJK 字符不足被判为噪声），
  `extractBody` 返回空串 → `handle()` 渲染出一张空白卡片，玩家像「点了没反应」。
- **修法**：`js/ai-response-handler.js` 的空正文兜底分支里，当 `_rescueProse` 也救不回时
  返回明确的降级提示「这一轮没有生成正文…请重新发送指令重试」。
  只改 `extractBody` 返回值，**不动 `handle()` 的章节推进 / 存档流程**，避免引入状态机风险。
- **验证**：浏览器探针用该步真实 raw 复现 → 返回降级提示；
  正常短句「他点了点头，转身走进风雪里，没有回头。」与正常长句均原样保留；零 pageerror。
- **状态**：已修复并验证。

### J-2　「而在公会」被误判成编造势力名（测试器误报，已修）

- **现象**：`freeworld / open` 报 `{"unknownFaction": ["而在公会"]}`。
  原句「…眼神里带着你熟悉的茫然。**而在公会**侧面的阴影里，几个穿着粗布短打的汉子…」
  ——「而在」是连词，后面接的是「公会侧面的阴影」，不是势力专名。
- **根因**：`t_player.py` 自带一套势力提取器（不是 `truthdiff.py`）。v4.08.0 修
  「需分心助盟 / 而非任何行会」时只同步了 `truthdiff.py` 的虚词表，
  `t_player.py` 的 `FAC_VAGUE_ANY` 漏了「而在」这类连词组合。
  误报会淹没真实缺陷，必须修，但**不能靠放宽势力后缀规则**来修。
- **修法**：`FAC_VAGUE_ANY` 补 `而在|而是|而非|而不|而且|然而|反而|从而|进而`；
  `FAC_SAMPLES` 新增「而在公会侧面的阴影里」「而是行会里的人」两条负样本。
- **验证**：判定器自检 **29 条样本全通过**（原 27 + 新增 2）；另用修复后的 `extract_factions`
  对 `freeworld/open` 的**真实落盘正文**离线复判：只提取到合法势力 `冒险者公会`，
  「而在公会」不再出现；把新增连词组合撤掉做反向对照，误报立刻重现 —— 证明是真修复，
  不是靠放宽势力后缀规则把问题藏起来。
- **状态**：已修复并验证。

### J-3　测试器末尾无 `__main__` 保护，被 import 会误启动第二个旅程（工程缺陷，已修）

- **现象**：本轮做 J-2 离线复判时用 `importlib` 加载 `t_player.py`，模块级 `asyncio.run(main())`
  被直接执行，意外启动了**第二个 38 界旅程进程**（占位 key 全部 401，75s 后被 timeout 杀掉），
  短暂突破「真实模型并发 1」硬约束。
- **影响核查（如实记录）**：主旅程日志 401 次数 **0**、进程未中断、
  `/tmp/yj_journey.json` 未被覆盖、无残留进程 —— 主旅程数据未受污染。
- **根因**：文件末尾直接 `asyncio.run(main())`，没有 `if __name__ == "__main__":` 保护，
  导致任何 import / 离线复判 / 单元测试都会跑一遍完整旅程。
- **修法**：加 `__main__` 保护；命令行执行行为不变。
- **验证**：`import t_player` 不再启动 main；判定器自检 29 条全通过；三脚本语法检查通过。
- **状态**：已修复并验证。

### J-4　产品降级提示被判定器当成正常正文 ✓（诚实口径缺口，已修）

- **现象**：`swallowedstar / act2` 日志为 `✓ (36字)`，但正文其实是产品降级提示

  变异灵敏度（把正则换成永不匹配，同一组断言必须失败）全通过；

- **状态**：已修复并验证。**报告里不再出现「兜底被写成通过」。**

### J-5　「负责家族」「转而回忆家族」被误判成编造势力（测试器误报，已修）

- **状态**：已修复并验证。

### J-6　空正文降级把「短正文」也吞掉（J-1 修复引入的回归，已修）

- **现象**：复跑数值清洗浏览器探针时发现，`extractBody` 对
  「三日后，他回到松木林。」「他摸了摸钱袋，总金币 99，转身进了酒馆。」

- **修法**：降级只用于「清洗后连 4 个中文叙事字都不剩」（`cjk < 4`）；

  `emptyNote` 兜底，不动章节推进 / 存档状态机。
- **验证**：新建可失败回归脚本 `yunjing-test/scripts/t_body_probe.py`（**15 例，真实浏览器**）：
  纯思维链 / 无中文短输入 / 纯标点 / 纯系统块 → 降级；空串 → 保持空串；
  短正文与清洗后短正文 7 例 → 原样或按清洗结果保留；中文数字零误伤；零 pageerror。
  **15/15 全通过**。探针从临时 `/tmp` 脚本收进仓库，防复发。
- **状态**：已修复并验证。

### J-7　语义复核追加告警查出正文末尾的协议 / 状态条残骸（真实缺陷，已修）

- **来源**：`semantic_judge.py --real` 对 `chaoshenxueyuan/act` 报 A 类告警。回查
  **玩家所见正文**，末尾确实是一整组没有任何叙事引导句的残骸：
  ```
  （）
  威胁逼近: 15/100
  world_update: faction.饕餮文明.influence=+2
  ```
- **为什么规则层与清洗层都漏了**：`_isSystemNoticeLine` 只认 `【】` / `「」` 外壳；
  面板残骸规则只认固定英文键（`tension|sanity|…`）；「容器.字段」规则要求点号在
  冒号**前**，而这里 `faction.饕餮文明.influence=+2` 的点号在冒号**后**。三条全不命中。
- **语义层的价值与边界（同时被验证）**：这是「规则层没报、语义层追加告警」的**真实命中**；
  但同批 17 条告警里也有明显误报 —— `douluodalu/act2 [A] HP x/y — 原文中未出现…
  此处为误报`（小模型自认误报却仍输出 issue）、「索托城」被当成凭空专名（实为原著真实地名）、
  以及 `dibao/act2` 那条自我纠结的长 `why`。所以语义层**只能追加告警**，
  不能单独作为放宽规则层的依据（K-4）。
- **修法**：清洗链新增三条「整行、短、无句读」的确定形态：
  ① 已知内部协议键（`world_update` / `variable_update` / `status` / `state` / `directive` /
  `actLog` / `snapshot`）；② 短字段 + 冒号 + 纯数值 / `N/M` 进度条；③ 孤立空括号残骸。
- **刻意不修的两类（避免误伤合法叙事）**：
  - `ditandali` 的「【怨气值 5/100。当前状态…】」嵌在叙述句里，是**系统流小说的世界观

  - `chaoshenxueyuan/open` 的「全息屏幕上…**基因亲和度：中**」有明确叙事引导句，

v4.08.0 第七节的 5 条「已知限制」在本轮逐条处理完毕：①③⑤ 与②中的「小模型自编数值」

**产品侧在既定硬约束内已无未闭环的确定性缺陷。** 以下不是「还没修的 bug」，
而是约束边界与能力事实，如实列出以免被误读成「已经完美」：

### K-1　小模型仍会编造，只是玩家看不到了

清洗层（`number-scrubber.js` + `ai-response-handler.js`）是产品侧确定性兜底，
不是模型能力升级。`t_scrub_effect.py` 逐份对比 raw / shown，量化「模型仍编造、
被兜底挡住」的数量，并单独统计产品降级提示次数 —— **清洗生效不等于模型变好**。
报告不得把「判定器变绿」写成「模型改善」。

### K-2　平台侧延迟与额度属外部平台特性

`agnes-3.0-flash` 的端到端延迟波动与额度限制不在产品修复范围。产品侧已有
MoNetGuard 指数退避 + Retry-After、首字节 / 流中空闲双超时、AbortController 取消、
MAIN_LATCH 并发门闩、`awaitPending` 防卡死、等待卡「⏹ 停止」、慢响应可见反馈。
本轮不虚构「修好了平台」。

### K-3　更强的生成模型不在硬约束内

用户限定只用 `agnes-3.0-flash` / `agnes-image-2.5-flash` / `agnes-video-2.5-flash`
三个免费档、不额外付费。这是约束边界，不是产品缺陷；v4.09.0 用语义判定层与确定性
清洗在白名单内补上了能力缺口。

### K-4　语义判定层只追加告警，不放宽规则层

小模型判小模型存在误报 / 漏报，语义告警必须与规则层交叉确认，绝不单独作为
「放宽规则判定器」的依据。规则层结果照单全收。

### K-5　广度旅程主进程用的是修复前脚本（口径说明，非缺陷）

`t_player.py all` 在 J-2 / J-4 修复前启动，进程内已加载旧判定器，源码修改不会
