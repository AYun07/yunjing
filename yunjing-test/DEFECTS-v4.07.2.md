### D-01　`M()` 工厂把状态函数接到 directive 键，常驻状态板对 4 界整体空白

- **严重度**：高（孤寒/玄剑/剑来/诡秘四界，玩家看不到任何模块状态）
- **现象**：`WorldExt.stripHTML()` 在 guzhenren / xuanjianxianzu / jianlai / guimi 四界返回 `null`，快捷指令条上方无模块状态区。其余 34 界正常。
- **触发路径**：打开孤寒传 → 完成开局 → 观察快捷指令条上方无模块状态区。
- **根因**（实测修正，早前判断有误）：
  `js/module-forge.js` 的 `M(id,icon,name,tip,stats,res,actions,directive)` 工厂把第 8 个参数接到 **`directive`** 键，
  而主界面常驻状态板 `js/world-ext/world-ext-core.js` 的 `stripHTML()` 只认 **`summary`** 协议。
  `js/world-runtime.js` 给每个模块补了默认 `summary`（无 `bp.summary` 时返回 `[]`），
  于是这四界 20 个模块的 `summary()` 恒返回空数组 → `continue` → `groups` 为空 → `return null`。
  **不抛错、只静默空白**，这是最坏的一类故障。
  wangyou 界正常，因为 `js/rpg-core.js` 的 rpg 模块显式写了 `summary: function (st) { return this.hud(st); }`。
- **修法**：
  1. `M()` 工厂同时补 `summary`，复用 `hud` 的 stats 兜底口径（同一份数值，不出现两处口径）；
  2. `stripHTML()` 兼容字符串型 summary（包成 `[{ i: m.icon, v: raw }]`）；
  3. `stripHTML()` 的空 `catch(e){}` 改为 `console.warn`——静默吞异常是这类故障能藏住的原因。
- **验证**：修后四界 `stripHTML()` 长度 783 / 786 / 1100 / 1104，状态板显示
  「💠30真元 / ☠️0毒性造诣 / 🏹0猎杀数 / 🧳0行商次数」等真实指标。
- **状态**：已修（待随版本发版）

### D-02　`tryPlayerKit()` 用覆盖写法顶掉本界专属模块 —— 13 界专属模块静默消失

- **严重度**：**极高**（本轮最有价值的发现；13 界专属机制整体失能，且无任何报错）
- **现象**：玄鉴仙族界实测只挂 3 个模块（面板/背包/自定义槽），
  而它的专属模块「符种坛 / 牲祭坛·箓气 / 族谱位阶」一个都没挂上；
  另有 12 界同样只剩 3 个随身器官（混沌学园 / 地球修仙 / 自由世界 / 轮回乐园 / 悬疑 / 全职高手 /
  神秘复苏 / 吞噬星空 / 完美世界 / 无限流 / 仙逆 / 玄鉴仙族 / 重生都市）。
- **触发路径**：打开上述任一界 → 完成开局 → 打开「界专属操作台」→ 面板空白，只有随身三件套。
- **根因**（浏览器内插桩定位）：
  `js/world-ext/world-ext-core.js` 的 `init()` 在 `DOMContentLoaded` 时执行，此时 PlayerKit 往往尚未加载，
  于是 `tryPlayerKit()` 首次返回 false，改由 `YJWait.for(tryPlayerKit, ...)` 延后重试。
  而界扩展的 `WorldExt.define()` 已经先跑完，把本界专属模块写进了 `modules`。
  重试成功时 `tryPlayerKit()` 执行的是 **`modules = got`（整体覆盖）** →
  本界专属模块被随身器官整片顶掉；此后 module-forge 的 `injectModules` 只能往随身器官上合并，
  本界专属模块**永久消失**，全程无报错、无告警。
- **实测证据**（修复前日志时序）：
  ```
  [WorldExt] xuanjianxianzu 界专属模块就位：符种坛 / 牲祭坛·箓气 / 族谱位阶
  [WorldExt] xuanjianxianzu 界无扩展文件，仅挂随身器官：家族度牒 / 家族行囊 / 万能自定义槽   ← 覆盖发生
  [ModuleForge] xuanjianxianzu 注入 6 模块
  ```
  最终模块列表 `['pkPanel','pkBag','custom']` —— 专属模块全丢。
- **修法**：
  1. `tryPlayerKit()` 改 `modules = got` 为 `modules = mergeDefs(got, modules)`（随身器官在前，本界专属保留）；
  2. `init()` 的触发条件从「一个模块都没有」改为「缺随身器官」——
     本界专属已就绪但 PlayerKit 晚到时，同样要补挂随身器官，否则功能缺一半；
  3. 日志改为「随身器官已挂载：…｜本界模块共 N 个」，让覆盖与合流在日志里可区分。
- **验证**：修复后玄鉴仙族界模块数 3 → **18**，`xjfuzhong / xjshengji / xjzupu` 三个专属模块全部回归。
- **状态**：已修

### D-03　`stripHTML` 空 catch 静默吞异常，故障不可观测

- **严重度**：中（掩盖故障，是 D-01 长期未被发现的直接原因）
- **根因**：`catch (e) {}` 空吞。任何模块 summary 抛错，状态板静默消失，日志无痕。
- **修法**：改为 `console.warn("[WorldExt:stripHTML] 模块 X summary 异常：", e.message)`。
- **状态**：已修

### D-04　`WorldExt.act()` 不返回动作结果，调用方拿不到任何反馈

- **严重度**：中（自动化探测与脚本全部瞎跑）
- **现象**：动作执行成功与否、失败原因，调用方一律拿到 `undefined`。
- **根因**：`js/world-ext/world-ext-core.js` 的 `act()` 里 `const toast = m.act(...)` 的结果只喂给 `showToast`，
  函数本身无 `return`。而 `js/world-runtime.js` 的 `act` **本来就返回结果字符串**——包装层丢弃它是接口契约不一致。
- **影响**：功能探测只能靠状态快照前后对比猜动作是否生效，误报与漏报同时存在（本轮 303 条噪声里相当一部分由此而来）。
- **修法**：`act()` 返回 `toast`（toast 与返回值共用同一份文案，不新增第二套口径）。
- **状态**：已修

### D-05　`gear` 模块 `add` 走弹窗输入，同步返回空串 → 调用方永远拿不到反馈

- **严重度**：低（用户侧有 toast 可见，程序侧无反馈）
- **根因**：`js/gear-core.js` 的 `action === "add"` 调 `manualAddSlot(s)`（内部 `UIDialog.prompt` 异步弹窗），
  同步 `return ""`，实际结果在 async 回调里产生。
- **修法**：同步返回明确文案「已打开「自建槽位」输入框（格式：槽位名|图标|匹配关键词）」，用户侧 toast 不变。
- **状态**：已修

### D-06　`WorldExt` 无模块清单接口，「本界装了哪些模块」无法回答

- **严重度**：中（阻碍验收能力，且属功能缺口）
- **根因**：`WorldExt` 只有 `modState(id)` 单查，无列表接口；各 ext 模块用 `WorldExt.define()` 直接注册原始对象，
  id 书写又不统一（`id: 'spacetime'` 单引号 / `id: "wr_patch_wangyou"` 双引号），
  自动化探测靠正则猜 id → 34 界被误判成「0 模块」，真实覆盖根本没测到。
- **修法**：新增 `WorldExt.moduleList()`，返回每模块的 `id / name / icon / type / actions / hasSummary`。
  `actions` 取法有坑：走 `WR.module()` 包装的模块，其 `actions` 被 `world-runtime.js` 列进 RESERVED 不挂到对象上，
  只能从 `WorldRuntime.registry()` 的原始蓝图读；而各 ext 直接 define 的对象则挂在自身上——两路都要兜。
- **状态**：已修

### D-09　数值型动作未校验 payload，非数字输入把状态写成 NaN 且不可自愈

- **严重度**：高（状态永久损坏）
- **现象**：道诡异仙界「清醒度」变成 NaN（实测 `主持补正：55 → NaN`），此后每次加减都是 NaN，状态板显示 NaN 且无任何报错。
- **根因**：`js/world-ext/daoguiyixian-ext.js` 的 `act` 写 `s.value + Number(payload)`，
  `Number("任意非数字")` 得 NaN，`Math.max(0, Math.min(100, 55 + NaN))` 仍得 NaN（Math 遇 NaN 传染）。
  同型缺陷另有两处：`quanqiubingfeng-ext.js`（防线 / 小区秩序）、`zhongshengdushi-ext.js`（暴露风险）。
- **说明**：变量上报路径是安全的（`WXH.asNum` 有 `Number.isFinite` 防护），缺陷只在**动作 payload** 路径。
- **修法**：写入前校验 `isFinite`，非法输入明确拒绝并保持原值。
- **状态**：已修（4 处）

### D-10　引擎结算结果从不回流 AI，AI 只能依据旧快照猜数值 —— 编造等级与自相矛盾的经验值

- **严重度**：**极高**（核心缺陷；直接破坏「网游数值由引擎结算、正文与面板一致」这一根本契约）
- **现象**（真实模型 `agnes-3.0-flash` 实测，wangyou 深度旅程 combat 步）：
  1. 「**经验+80。当前经验 80/62**」——当前经验 80 超过所需上限 62，自相矛盾；
  2. 「经验条满格转了一圈——**Lv.2了**」——玩家实际 Lv.1，一次战斗经验（伤害/20，约 35）不足以升级；
  3. 任务目标写「击杀 3 只「野狼」（**Lv.2**）」——给野怪标注具体等级，正是提示词明令禁止的。
- **根因**：`js/rpg-core.js` 的动作结算结果（如「击杀！野怪掉落 30 金币、声望 +1、经验 +45」）
  **只回传给界面**（toast / 面板 `st.log`），从不进入 `directive`（即 AI 提示词）。
  AI 每轮拿到的永远是**动作前**的快照（经验 0/62），于是只能靠猜：
  它不知道刚才打了谁、掉了多少、经验加了多少、是否升级 —— 于是编。
  换言之：**玩家看得见真相，AI 看不见**，两者信息不同源。
- **修法**：
  1. `ok()` 统一把动作结果记入 `st.actLog`（保留最近 5 条）；
  2. `directive` 增加【上一轮动作结算 · 引擎已判定 · 必须照此写】段（正常档最近 3 条 / 低配 tiny 档最近 2 条），
     明确「结算里没有的数值一律不得凭空出现，也不得说『升级了』除非结算里明写了」；
  3. 战斗结算文案改为**不带野怪等级与 HP**（原先含「目标 HP 53/125」，AI 照抄就会写出野怪 HP），
     改为带**动作后的玩家等级与经验**（「当前 Lv.1 经验 4/62」），让 AI 判断是否升级有据可依；
  4. 结算段追加「结算里出现的怪物名不得在正文里加注等级、HP 或品级」。
  5. `initState` / `normalizeState` 补 `actLog` 数组，老存档自动兼容。
- **验证**：浏览器内实测 —— 打怪、掉落、休整三步后，`directive` 正确带出三条结算，
  含「当前 Lv.1 经验 4/62」，页面零错误。
- **状态**：已修

### D-11　判定器把 NPC 等级当成玩家编造等级

- **严重度**：中（验收口径失真）

### D-12　势力判定把「此刻没有行会」「那个行会」当成编造势力名

### D-13　旅程测试超时阈值过低，平台延迟被误报成产品故障

- **严重度**：高（测试自身失效；会掩盖真实缺陷）
- **现象**：wangyou 深度旅程 12 步里 8 步报 `TimeoutError`。
- **根因**：超时设 80s，而 `agnes-3.0-flash` 端到端延迟实测波动 5.8s ~ 62.8s，
  长正文（420 tokens）更慢 —— 是平台慢，不是产品坏。
- **佐证**：绕开浏览器直接调接口，同样出现 62.8s 超时；连续三次探测为 25.1s / 5.8s / 38.8s。
- **修法**：超时放宽到 180s（`YJ_TIMEOUT` 可调）。放宽后 13 步全部返回，零超时。
- **状态**：已修

### D-22　`ee*` 动作的返回值被丢弃，多个早退分支静默无反馈

- **严重度**：中（安全屋经营线 8 个动作对所有程序化调用方都是「点了没反应」）
- **现象**：`WorldExt.act('quanqiubingfeng','eeJob','张三=守夜')` 返回 `undefined`；
  点「撤销工单」「请出住户」「派工」找不到目标时，界面不弹任何提示，玩家以为程序卡了。
- **根因**：
  1. `WorldExt.act()` 对 `ee*` 走的是 `entAct(...)` 分支，改动 D-04 时只修了 `m.act` 分支，这条分支被漏掉，
     且 `entAct` 自身也没有 `return toast`；
  2. `entAct` 内多处早退是裸 `return`（`if (!def) return;` / `if (i < 0) return;`），
     既不提示也不刷新面板。
- **修法**：
  1. `entAct` 末尾 `return toast`；`WorldExt.act` 的 `ee*` 分支 `return entAct(...)`；
  2. 全部早退路径改为给出可读提示（`未找到该工程，无法开工` / `队列中没有可取消的工程` /
     `名册中没有「张三」` / `格式：姓名=分工，如 张三=守夜`）。
- **状态**：已修

### D-23　`eeDropOp` 未校验索引，非数字输入会误删第一张工单

- **严重度**：中（一次误操作会毁掉玩家待确认的行动）
- **现象**：`ent.ops.tickets.splice(Number(payload), 1)`，
  payload 为非数字时 `Number()` 得 `NaN`，而 `splice(NaN, 1)` 被当作 `splice(0, 1)` —— 删掉的是第一张工单，
  且没有任何提示。
- **根因**：输入未校验，与 D-09（数值型动作未校验 payload）是同一类，但后果是「误删」而非「写坏状态」。
- **修法**：先校验 `Number.isInteger(idx) && idx >= 0 && idx < 队列长度`，非法则提示 `工单序号无效（应为 1～N）`；
  合法时提示 `已撤销第 N 项待确认行动`。
- **状态**：已修

### D-24　`WorldExt.act()` 传入不存在的模块 id 时静默返回

- **严重度**：高（静默失败是这类缺陷最好的藏身处，本轮实测直接踩中）
- **现象**：调用 `WorldExt.act('skill','斩')` 返回 `undefined`、界面无任何反应。
- **根因**：`act()` 开头 `const m = modules.find(...); if (!m) return;` —— 模块不存在时直接返回。
  后果是**任何传错模块 id 的调用方（脚本、小云工具、自动化测试）都无从察觉**，
  还会以为「动作执行了但没效果」。
- **实测关联**：本轮玩家旅程测试正是把动作名当模块 id 传（见 D-27），
  13 步里 10 步的动作一个都没真执行，全程零报错 —— 若 `act` 对此有提示，
  这个问题在第一轮就会被立刻发现。
- **修法**：模块不存在时返回 `未找到模块「<id>」` 并 `showToast(msg,'warn')`，
  让调用方能区分「动作没生效」与「模块不存在」。
- **状态**：已修

### D-25　`Number(x) || -1` 哨兵写法把合法的 `0` 误改成 `-1`

- **严重度**：中高（委托板反复重建，玩家点的委托会凭空消失）
- **现象**：`f.quests.boardDay = Number(f.quests.boardDay) || -1;`
  而 `boardDay = 0`（第 0 天）、`boardLv = 0`（Lv.1–4 档）都是**合法值**，
  `0 || -1` 短路成 `-1`（=「从未刷新」的哨兵）。
- **后果**：`refreshBoard()` 的 `if (!force && q.boardDay === day && q.boardZone === st.zone && q.boardLv === lvBucket) return 0;`
  因 `0 !== -1` 恒不成立 → **每次调用都整块重建 offer** →
  玩家刚点下的委托可能凭空消失，提示变成「这条委托已经不在板上了（世界局势变了，或已被他人接走）」。

### D-34　「委托报酬」被 AI 误读为已到账，导致正文凭空多出金币、经验与升级

- **严重度**：**高**（正文骗玩家：玩家实际没拿到，AI 却写成已到手并自行升级）
- **现象**：真实模型正文写：
  ```
  【系统】：奖励结算：金币 +46，经验 +64，声望 +4。
  【系统】：你当前经验值：68/62……
  【系统】：升级！等级提升至 Lv.2。
  ```
  而引擎实况是：**交付失败**（委托 0/3 未完成），金币未变、经验未变、等级未变。
  `68/62` 是 AI 把「经验 +64」加到当前经验 4 上自己算出来的 —— 68 超过上限 62，自相矛盾。
- **根因**：
  1. 「接取委托」的结算文案写「报酬 46 金币 + 64 经验 + 4 声望」，

  2. `directive` 的「手头委托」段只列标题与进度，没有提醒报酬是预告；
  3. 结算文案只给**增量**（+N），AI 自己去和快照的当前值相加 —— 于是算出 68。
- **修法**（四处配合）：
  1. 接取文案改为「**完成后可得** …（**尚未到账**，交付后才会入账）」；
  2. `directive` 新增「【委托报酬尚未到账】」段：未交付前正文不得写成「已获得 / 到手 / 领到」，也不得写因此升级；
  3. 结算段补一句「结算里的「+N」是**本次增量**，当前值一律照抄上方快照，**绝不可自行相加**」；
  4. 引擎侧同时留 `st.goldTrail`（余额与变动额流水），供判定器以真值核对。
- **状态**：已修

### D-36　「行动选项」排在正文**前面**时，整段正文被剥离规则吞掉

- **严重度**：**高**（玩家直接可见：正文一个字都不剩，卡片是空的）
- **现象**：38 界广度旅程实测（scifi 界 act2 步）：模型返回
  ```
  【行动选项】
  1. 【快进】直接走向星门……
  …（共 6 条）
  (variable_update)
  我.location: 边境星域·废弃矿区·中转站大厅
  …
  /variable_update我站在中转站大厅的阴影边缘，手指无意识地摩挲着腕带内侧的磨损处。……
  ```

- **根因**：`ai-response-handler.js` 剥行动选项用的是一刀切：

- **修法**：改为「只剥标题行 + 其后的选项条目行，遇到非选项行即停」；
  若选项段之后没有正文（rest 长度 < 15），仍按旧行为整段删除（保持「选项在结尾」的原有表现）。
  新增 `_isOptionItemLine()` 判定六种编号形态（`1.` / `1、` / `1)` / `①` / `A.` / `【快进】`）。
- **验证**：同一份 raw 复测 → extractBody 输出 1412 字完整正文，开头结尾正常；
  回归用例「正文 + 结尾型选项段」仍整段剥掉、「正文 + 选项段 + 后续正文」正确只剥选项。

- **状态**：已修（同一份 raw 复测 → extractBody 输出 1412 字完整正文；回归用例「结尾型选项段」仍整段剥掉、「选项段 + 后续正文」正确只剥选项）

### D-26　压力探测用正则扫 JSON 找 NaN，把字符串 `"NaN"` 误判为数值 NaN

- **严重度**：中（46 条噪声，险些把真缺陷淹没）
- **现象**：几乎所有界都报 `wr_npc add → 状态含 NaN/Infinity`。
- **根因**：探测器用正则 `(?<![\w.])(NaN|Infinity)(?![\w])` 扫 JSON 字符串，
  而 JSON 里字符串值 `"NaN"` 同样会被匹配 —— NPC 名就叫「NaN」，是**字符串**不是数值。
  与 D-17 是同一类问题：判定口径不精确造成的假阳性。
- **修法**：改为在浏览器侧按对象结构遍历（`typeof v === 'number' && !isFinite(v)`），
  只认真正的非有限数值，不再靠正则猜。
- **状态**：已修

### D-27　旅程测试把「动作名」当「模块 id」传，13 步里 10 步的动作一个都没真执行 —— **结算回流从未被真正验证**

- **严重度**：**极高**（本轮最有价值的发现；此前对 D-10 的「已验证」结论是无效的）
- **现象**：第一轮 wangyou 深度旅程 13 步全部「跑完」，但：
  - 快照恒为 `lv=1 / gold=50 / hp=403 / round=0`——**战斗没推进轮次、交委托没加钱、买药没扣钱**；
  - 10 个带动作的步骤全部静默无效；
  - 却因「没有报错」而被当成通过。
- **根因**：`WorldExt.act` 的签名是 `(模块id, 动作id, 参数)`，
  而 `DEEP` 计划写成 `("skill","斩")` —— 第一参传的是**动作名**，
  `act()` 去找名为「skill」的模块，找不到就静默 `return`（正是 D-24）。
  于是 AI 每轮拿到的都是**动作前**的快照，从未收到任何引擎结算。
  连带后果：D-10「结算回流 AI」这项修复**在第一轮根本没有被验证过**，
  当时 combat / class 两步「通过」只是因为正文里恰好没写金币与等级。
- **修法**：
  1. `DEEP` 每步改为 `(模块id, 动作id, 参数)`，模块 id 补 `wr_rpg`；
  2. 参数改用引擎真实格式（`skill`=技能 id、`teleport`=地图索引、`qaccept`/`qturnin`=委托 id）；
  3. 新增动态占位符（`@killOffer` / `@active0` / `@map1`），从**动作前的真实快照**取引擎实际 id
     ——玩家是看到按钮才点的，不会凭空知道委托 id；
  4. 步骤顺序按真实玩家路径重排：转职 → 接委托 → 做委托 → 交委托；
  5. **动作执行结果必须校验**：返回 `undefined` 记 `actNoop`、返回「未找到模块」记 `actBadModule`，
     不允许再出现「动作没跑但全程无报错」。
- **状态**：已修（修正后深度旅程已重跑，结果见交付报告）
