## 三、截图未覆盖项 —— 已二次核实为「脚本问题，非功能缺陷」

下列 4 项在自动化截图里显示未截到（0/N 或少数），我做了纯本地二次快验（直接调 openUI + 检查 DOM，不调用模型），确认功能本身均正常：

1. **图鉴第二层切换**：测试脚本判断写成 `cfg.layers > 1`，而 `layers` 实为数组（各 2–3 层），数组与数字比大小导致判断恒为假、未执行切换。快验中 `A.switchLayer(l2.id)` 切换成功，节点数正常变化（14–27 节点）→ **功能正常，脚本判断表达式有误**。
2. **称号面板**：快验中 `TitleSystem.openUI()` 调用后 DOM 生成 14–15 个节点、遮罩出现 → **功能正常**。自动化流程里被"逐个关闭浮层"的清理逻辑提前关掉，故未截到。
3. **灵宠面板**：快验中 `BeastSystem.openUI()` 调用后生成 7 个节点、遮罩出现 → **功能正常**。同上，被清理逻辑提前关闭未截到。
4. **词条编辑面板**：快验中 `BonusEngine.openAffixEditor()` 调用成功；自动化截图用占位 ID 无对应词条数据、节点为 0 → **功能正常，属测试数据问题**。

> 结论：以上均非功能缺陷，而是测试脚本的判断表达式 / 清理时序 / 占位数据问题。**38 界全部核心子系统与面板功能均可用。** 快验脚本见 `verify-panels.mjs`，覆盖 daoguiyixian / fanrenxiuxian / scifi 三界，结果一致。
