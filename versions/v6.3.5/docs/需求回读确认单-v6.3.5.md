# 云境 v6.3.5 · 需求回读确认单（对话重 roll / 回档）

> 本单按交付流程「听懂 → 拆解」产出。假设未写明不拆任务；验收句未回读确认不排期。
> 用户原话：「云境也要做到某一轮对话结果不满意可以重roll或者回档到上一轮或者某一轮」

## 一、需求四问

**Q1 要解决什么问题？**
玩家对某一轮的生成结果不满意（写得不好 / 剧情走偏 / 变量登记错），想：①换一种写法重来；②退回上一轮；③退回指定的某一轮再从那里继续。现在云境只能弹末轮栈顶，且入口藏在每一轮正文卡底部——虚拟滚动开启时旧楼卡片被回收，玩家滚上去也点不到，等于「只能改最后一轮」。

**Q2 现在系统真实能力是什么？（查证结果，非假设）**
- `story-framework.js`：已有完整轮次快照栈 `turns[]`，每轮压 `varsBefore / histLen / digestBefore / driftBefore`；`restoreTurn()` 能精确回滚单轮的变量、历史、摘要、漂移、DOM 卡片。
- `StoryInput.regenerate()`（↻ 重新生成末轮）、`rollback()`（↩ 回退末轮）已实现且可用，但**只能操作末轮**。
- `chat-virtualizer.js`：DOM 只留约 106 楼，旧楼卡片会被回收重建——卡底部按钮对历史轮不可靠。
- 快照栈硬上限 **40 轮**（超出 `shift()`）；更早轮次的变量状态已被裁剪，无法精确还原。
- 全量对话另存 IndexedDB transcript，回档时若不同步截断，刷新后旧剧情会「复活」。

**Q3 完成的定义（验收句）是什么？**
逐条如下，每条都可在真浏览器验证：
1. **重 roll 当前轮**：点「↻ 重新生成」，同一条玩家指令重新生成，正文变化；轮次号不重复增长；该轮变量/摘要按"该轮开始前"现场重算，不残留上一次结果。
2. **回退上一轮**：点「↩ 回退本轮」，末轮正文/变量/卡片/轮数整体撤销，故事停在该轮开始前；二次确认后可撤销的保护仍在。
3. **回档到指定轮（核心新增）**：打开「时光轴」，列出最近 40 轮（轮号 + 玩家指令摘要 + 生成时间/字数）；点某轮「回档到此」→ 连续回滚到该轮开始前，变量/历史/摘要/DOM/虚拟滚动缓冲/IndexedDB transcript 全部同步，刷新页面后停在该点、被丢弃的后续剧情不复活。
4. **指定轮重 roll**：时光轴某轮点「从此处重写」→ 回滚到该轮开始前并用该轮原指令重新生成，后续轮次被丢弃（有明确警示）。
5. **窗口边界**：超过 40 轮之前的轮次不出现在时光轴，界面明示"仅可回档最近 40 轮"，不承诺做不到的任意轮。
6. **生成中保护**：创作进行中（isProcessing）或变量 AI 未落定时，所有回档操作被守卫，不出现半截状态。
7. **零回归**：原有 ↻/↩、读档、翻页、虚拟滚动、存档完好校验全部不破坏；真浏览器零 pageerror、零 404。

**Q4 不做什么（边界）？**
- 不做"无限历史回档"——快照 40 轮硬上限是内存治理的既定护栏（DR-036），本版不放大。
- 不自动裁剪/删除更早的 IndexedDB transcript 正文——回档只同步"当前档的活跃 transcript"，历史全量仍可导出，避免动玩家剧情正文（承接 DR-036 边界）。
- 不做分支剧情树（回档后生成新分支、保留旧分支）——本版是"覆盖式回档"：回档即丢弃该轮之后，符合大多数单机文字游戏心智。
- 不改存档格式版本。

## 二、假设清单（未确认前不视为承诺）

- **A1（语义）**：「重roll」= 用同一条玩家指令重新生成当前轮；「回档到上一轮」= 现有 rollback（末轮撤销）；「回档到某一轮」= 回滚到该轮**开始前**并停在那里、由玩家重新发令。若用户想要"保留该轮正文、只改下一轮"，语义需调整。
- **A2（覆盖式）**：回档到中间某轮后，该轮之后的轮次被丢弃，不保留分支。
- **A3（窗口）**：用户接受的"某一轮"= 最近 40 轮内的任意轮；更早的因快照裁剪无法支持，界面明示。
- **A4（入口）**：时光轴入口放在创作室工具箱（与「存档体检」「世界舆图」同级），不改动正文卡片现有按钮（避免与虚拟滚动冲突），现有 ↻/↩ 保留给末轮快捷操作。

## 四、用户已确认的权衡点（2026-11-22）

- **回档语义 = 两种都要**：时光轴每轮同时提供「回到本轮开始前（丢弃本轮及之后）」与「保留本轮、只丢之后」两个动作。
- **任意回合回档**：用户明确要求"选定任意回合回档"，不止最近 40 轮。
  - 为此需突破 40 轮热栈限制：给每轮快照全量落一份到 IndexedDB（`turnHistory/<genre>`），时光轴读取全部轮次。变量快照是轻量结构化数据（不含图片），存 IDB 不占 localStorage、不与 DR-036 内存治理冲突。
  - 老存档没有全量 IDB 快照的，降级为 40 轮热栈内可选，界面明示。
- **入口 = 时光轴 + 卡片按钮都做**：
  - 工具箱新增「时光轴」面板，列出全部可回档轮次，每轮两个动作 + 选定任意回合。
  - 每轮正文卡片的 ↻/↩ 按钮补上 `data-turn` 轮号，改为操作**对应轮**（而非末轮）；虚拟滚动重建的卡片同样带轮号。

## 五、对 A1/A3 假设的修订（用户确认后）

- A1 修订：两种语义并存——"回到本轮前"与"保留本轮丢之后"；重 roll = 回滚到该轮开始前用原指令重发。
- A3 修订：任意回合（不限 40 轮）可回档，通过 IDB 全量快照实现；40 轮热栈仅作快速路径与老档降级。
- A2、A4 维持；A4 入口扩展为时光轴 + 卡片按钮双入口。
