# 云境 v3.90.0 · 视觉合理性审查报告

> 本文件是**验收口径**的一部分，不是发布说明。它回答的问题是「视觉上哪里不合理」，
> 与 `LIVE-TEST-v3.90.0.md` 回答的「能不能用」并列，两者不能互相替代。

## 0. 为什么有这份报告

v3.89.0 的验收证据全部是**功能口径**：33/33 加载通过、自检 63/63、4 页零 404、按钮零重叠零尺寸、
8 套主题「颜色指纹两两不同」。这些只能证明页面**能用**，一条都不能证明页面**视觉上合理**。

用户明确提出两点纠偏：

1. 「现在的大厅不是我们一开始设计的那样，怎么还是这种老套俗套的排版版式」；
2. 「测试的时候不能只是测试能不能用，而且要从视觉层面上看到有没有什么地方是不合理的」。

本报告把第 2 点固化成可复用、可判失败的验收维度，并记录第 1 点的取证与整改过程。

## 1. 口径：什么叫「视觉不合理」

每一条都必须能判 `FAIL`，不接受「看着还行」这种结论。

| # | 维度 | 可判失败的判定句 |
|---|---|---|
| V1 | 视觉焦点 | 首屏是否存在唯一主焦点；若有 ≥2 个元素争抢注意力，或根本看不出该看哪，判 FAIL |
| V2 | 版式辨识度 | 版式是否为「标题 + 一排胶囊 + N 张等大卡片」的通用模板；若 8 套主题只是换配色而骨架相同，判 FAIL |
| V3 | 留白与密度 | 是否存在大片无意义空白（>30% 首屏且无构图意图），或内容挤在一条窄带里，判 FAIL |
| V4 | 信息层级 | 主标题 / 区块标题 / 卡片标题 / 说明文字的字号与字重是否拉开；若两级对比不足、读不出主次，判 FAIL |
| V5 | 形态与比例 | 卡片是否全部等大等高、等圆角、等描边；若无节奏变化且比例失调，判 FAIL |
| V6 | 对齐与遮挡 | 是否有元素错位（如按钮跑到卡片右上角脱离内容流）、被裁切、被浮动吉祥物或气泡遮挡，判 FAIL |
| V7 | 可读性 | 文字是否被挤成竖排断行、过小、截断、对比不足，判 FAIL |
| V8 | 可发现性 | 首屏是否至少有 1 个完整可点击入口；横向/纵向滚动是否有可见提示，判 FAIL |

**判定方式**：真实浏览器截图交由视觉审查逐张按 V1–V8 出结论；脚本的「零 404 / 零重叠」只作为辅助，
**不得**代替视觉结论。

## 3. 根因：为什么「不是一开始设计的那样」

三方对照（v3.55.7 → v3.84.0 → v3.89.0）显示，**主界面骨架从项目第一个版本起就没变过**：

```
吉祥物立绘 →「云境」标题 → 一排胶囊标签 →「五大类型工坊」→ 5 张等大等圆角卡片 → 底部统计
```

变的只有配色（暖金暗蓝 → 紫 → 紫粉渐变）。

同时，git 历史里从 `v3.84.0`（提交语「六套异构风格 + 切换坞」）起就存在 **14 套异构版式概念稿**，
每套有独立 DOM 骨架：罗盘是绝对定位环形节点、轮播是 100vh 横向舞台、侧栏是固定 248px 分栏、
卷轴是纵向 scroll-snap 场景、杂志/瑞士网格/终端/手帐各不相同。这些稿子**从未成为 `index.html` 本身**。

v3.89.0 的整改把这 14 个 demo 页当作「该清理的散页」全部删除，只把 8 个主题名提炼为
`css/lobby-themes.css` 里的**配色变量 + 圆角微调**。所以结论是：

> **换皮没换版式。** 继续调颜色永远修不好「老套俗套」，必须动布局骨架。

## 4. 修正前：逐套视觉问题清单

按 V1–V8 对第一版异构落地（8 套 × 2 视口）实拍审查，记录到的**真实视觉缺陷**：

### P0 · 跨 8 套共通（16 张截图全中）

| 问题 | 维度 | 具体表现 |
|---|---|---|
| 小云默认气泡首屏自动弹出 | V6 | `rotateTips()` 每 900ms/7s 弹白色气泡，压住 colorful 第 3 张大卡、carousel 第 2 张、hero 第 3 张、avatar 第 5 张、compass 罗盘右侧等 |
| 「入坊 →」跑到卡片右上角 | V6/V7 | 基础 `.ws-enter{align-self:flex-start}` 在 `flex-direction:row` 的卡片里变成顶部对齐，与名称分离，像渲染错位 |

### P1 · 逐套缺陷

| 主题 | 维度 | 具体表现 |
|---|---|---|
| ③ carousel | V7/V3 | 标题被挤成「悬疑推 / 理」「科幻未 / 来」竖排两行；卡片上半部整片空白 |
| ⑥ scroll | V8/V3 | masthead 占 62vh，首屏只有标题，第一张卡只露出半个圆形图标，无滚动提示，像没做完 |
| ② compass | V6/V7 | 罗盘 660px 偏大偏下，第 5 个节点被首屏裁掉；节点名称 12px 过小；中央核心文字偏糊 |
| ⑤ hero | V3/V6 | 巨幕卡下半部约 40% 空白；右侧第 4 张卡被首屏底边裁切 |
| ① colorful | V3 | 3 张大卡中间出现大块垂直空洞（内容堆在上、入坊在底） |
| ⑦ sidebar | V5/V6 | 5 张卡排成 4+1，第 5 张孤零零留右侧大片空白；主题切换器压在侧栏顶部内容上 |
| ④ film / ③ carousel | V8 | 横向滚动没有任何「可滑动」提示，第 2/3 格被裁切后玩家不知道能滑 |
| 手机端 sidebar | V7 | 桌面 6 列 `span` 规则在 390px 下仍生效，5 张卡挤成 3 列窄卡、文字竖排 |
| 手机端 colorful/avatar | V5 | 2 列下第 5 张成孤卡 |
| 全部主题 | V3 | masthead（吉祥物+标题+7 个胶囊+区块标题）吃掉首屏 40–50%，卡片区被推到屏幕下方 |

### 其余观察

- 8 套里 `avatar`（竖长人物卡）是修正前视觉最完整的一套；`scroll` 最差。
- 手机端 7 个胶囊标签占两行，进一步挤压首屏。

## 5. 修正后：逐套结论

| 主题 | 骨架 | 本轮修掉的视觉问题 | 修正后状态 |
|---|---|---|---|
| ① colorful | 3 张大形象卡 + 2 张横向小卡 | 大卡改「上部大形象位 + 下部文案」消掉空洞；入坊回正；小卡第 5 张跨列 | 焦点落到卡片，非模板化 ✓ |
| ② compass | 520px 环形罗盘 + 5 节点 + 中央核心 | 缩小上移使 5 节点全进首屏、字号 13px、核心放大 | 完整可辨 ✓ |
| ③ carousel | 横向 scroll-snap 大画幅 | 卡片改上下分区、标题 `nowrap`、入坊归位、加横滑提示与常驻滚动条 | 文字不再竖排 ✓ |
| ④ film | 胶片条 + 4:3 画格 + 齿孔 | 加横滑提示与滚动条、分区间距 | 装饰不喧宾夺主 ✓ |
| ⑤ hero | 1 张全高巨幕 + 右侧 4 行列表 | 巨幕内容垂直居中 + 大形象位、降高让第 4 张进首屏、入坊回正 | 主次清晰 ✓ |
| ⑥ scroll | 纵向逐屏左右交替长卷 | masthead 62vh→34vh、首屏露出完整第一入口、加「↓ 向下展卷」、清掉溢出的光晕方块 | 不再像空屏 ✓ |
| ⑦ sidebar | 固定 248px 侧栏 + 右侧 3+2 网格 | 消除孤卡、切换器移到右上、侧栏内容靠上；手机端回退 2 列 | 不再挤压 ✓ |
| ⑧ avatar | 5 张竖长形象卡 | 第 5 张手机端跨列 | 保持最完整 ✓ |

**跨套修正**：大厅页不再自动轮播小云气泡（玩家点小云才出现，创作室保留）；统一压缩 masthead；
手机端隐藏胶囊、孤卡跨列、横滑区补分隔节奏。

修正后 16 张截图重新实拍审查：**白色气泡遮挡 0 处、竖排断行 0 处、孤卡 0 处、
首屏无完整入口 0 套、控制台错误 0**。骨架指纹 8/8 两两不同。

  已有 `@media(max-width:760px)` 兜底，但 768/1024 未单独验。
- **320px 极窄屏、iPad 竖屏、横屏**未覆盖。
- **真实 API 33 界生成本轮未重跑**：本轮改动范围是大厅 CSS / 首页版式 / 首页小云气泡，
  不触及 `studio.html`、创作室模块与 API 链路；沿用 v3.89.0 的 33/33 结论，不冒充本轮结果。
- **深色/浅色系统偏好、`prefers-reduced-motion`** 未做适配审查。
- 修正后 `carousel` / `film` 手机端横向区与下方「开放世界扮演」长标题之间仍有轻微割裂感
  （已加 18px 分隔，未做进一步视觉重构）。
- **视觉审查含主观判断**：本报告的技术口径是 V1–V8 全部判通过；**用户口径以你实际打开后的观感为准**，
  两者不一致时以你的为准，按下一批处理，不悄悄扩范围。
