## 2. 本轮修掉的问题

| 问题 | 现象 | 处理 |
|---|---|---|
| 地球界不是真实世界地图 | 两张抽象色块图（东半球/西半球），大陆是椭圆拼的，城市坐标手摆 | 换成 Natural Earth 1:110m 真实陆地轮廓（1606 点 / 16KB 内嵌），等距圆柱投影，24 个城市按真实经纬度落点，合并为一张「世界 · 七洲四洋」 |
| 图鉴一开小云就压字 | 小云招呼气泡正好盖住地图详情与节点说明 | 开图时给 `body` 加 `atlas-open`，小云退场 |
| 节点标签互相压字 | 欧洲/中国区 8–10 个名字叠在一起 | 加标签避让：按「当前位置 > 已到访 > 其余」排序，逐个试右/左/上/下四个位，四投不中只留圆点 |
| 资料库小节标题被当地标 | 「主要国家概况」「主要山脉与河流」这种目录名被画到地图正中央 | 标题类词条不再上图（概况/总览/体系/时间线/主要X与Y…） |
| 「迷雾未开」大印压节点 | 开局印章固定在正中，正好压住起点 | 移到下方空白区、降到 0.55 透明度、画在道路之下 |
| 起点旗标糊成色块 | 「你在这里 / 整装待发」小旗在经纬坐标下渲染成一团 | 去掉旗标，改由节点光环 + 详情「◈ 当前位置」表达；节点加 `data-mode` 便于验收 |
| 斩神界没有起点 | 13 个节点无一标 `start`，开图空转 | 旧城街区补 `start`，并在 `resolveCurrent` 加兜底（退到首层首节点） |

## 3. Token 实测（不是估算，是抓包）

方法：本地起 mock `/v1`，抓每一次请求的 body，逐条量字符。

| 指标 | 实测 |
|---|---|
| 每轮 API 请求数 | **1 次**（变量登记走正文内嵌块，不起独立请求） |
| 开篇请求数 | 1 次 |
| 系统提示词 | 26,466 字符（约 1.8 万 token） |
| 历史消息 | 上限 17 条，助手正文压到 ≤900 字符/条（头 500 + 尾 300） |
| 可在服务端命中的稳定前缀 | 18,240 / 26,556 = **68.7%** |

**已做**：入场指令只在开篇有效、档案 18 字段示范只在前 5 轮有用——按回合数裁掉，规则一条不少。
实测系统提示词 26,466 → 25,983（第 2 轮起），第 5 轮起再减 694。

**没做、也不打算偷偷做**：把 4,031 字的《原著骨架速查表》改成按需检索能再省约 15%，但它承载境界阶梯、势力谱系、人物志、年表——一旦该轮没检索到，设定就会漂。这属于「改 33 个配置文件」的批量改动，必须逐界验证，放进下一批，不混在这次里。

## 4. 未验证项（必须说清楚）

- 真实 API 下的长局（100+ 回合）成本曲线没有实跑，只有 4 轮抓包；历史压缩比按代码上限推算。
- 地图只在桌面 1440 与 390 手机各看了一轮，平板宽度没做专项。
- 33 界全量测的是「结构与交互链路」，**不是每一界的剧情质量**——剧情质量只能靠真人对局。
- 结论含主观视觉判断，最终以你打开后的观感为准。
