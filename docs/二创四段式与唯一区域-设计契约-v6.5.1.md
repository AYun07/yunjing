# 二创四段式与唯一区域 · 设计契约（v6.5.1）

## 1. 范围
把 v6.5.0 二创版块从"单段 note + 散落包体"改造为"四段式正文 + 唯一区域"。只改二创版块，不动主线玩法/存档/回档/战力。

## 2. 唯一区域（A1/A2）

```
云境内：工具 → 二创版块（唯一入口，ch-root）
   ├─ 浏览列表   ← GET Issues?labels=二创投稿（唯一标签）
   ├─ 发布向导   ← 四段式表单
   └─ 增量安装   ← 沿用 v6.5.0
GitHub 侧：
   ├─ Issues[label=二创投稿]  ← 唯一索引区，每件作品一个 Issue，按 created_at 倒序
   └─ community/packages/     ← 唯一包体目录，一件作品一个 .zip.b64
community/README.md           ← 区域规约：禁止第二标签/第二目录
```

- `github-client.js` 固定 `LABEL='二创投稿'`，封死 `setRepo` 之外的标签写入口；发布只走 `postFanwork`（该标签）。
- 包体上传统一 `PUT community/packages/<slug>-<ts>.zip.b64`（via git data API，与推主程序同一套权限）。
- 禁止行为：不得新建其它标签归档二创、不得把包体写进 Gist 或个人仓库。代码里不留第二存储分支。

## 3. 四段式正文 schema（A3/A7）

Issue body 用标记包裹四段，向下兼容旧 `<!--YJ_NOTE-->`：

```
<!--YJ_V2-->
## 简介
<!--YJ_INTRO-->作品一句话概述<!--/YJ_INTRO-->

## 特点
<!--YJ_FEATURE-->亮点1；亮点2<!--/YJ_FEATURE-->

## 二创内容
<!--YJ_CONTENT-->DLC×2；存档×1；预设×1（逐项 key 清单）<!--/YJ_CONTENT-->

## 打包源码
<!--YJ_PACKAGE-->{"path":"community/packages/xxx.zip.b64","sha256":"...","size":3586,"files":["manifest.json","content/0.json",...]}<!--/YJ_PACKAGE-->
<!--/YJ_V2-->

<!--YJ_GIST-->{...兼容旧安装器...}<!--/YJ_GIST-->
```

- `manifest.schema` 升 3，新增 `intro/features/contentSummary/package` 字段，保留 `note` 兼容。
- 解析优先级：有 `YJ_V2` 走四段；无则回退 `parseNote` 单段（A7）。

## 4. 发布表单（A4）

四段对应四个输入，必填校验：
- 简介（textarea，1–300 字）
- 特点（textarea，1–500 字）
- 二创内容：由 `PatchEngine.diff` 结果**自动生成**清单（kind + key），只读展示，不手填
- 打包源码：由 `ZipWriter.makeZip` 生成，段内展示文件清单 + 大小 + sha256，包体自动上传

四项确认勾选沿用 v6.5.0，新增"我确认四段信息如实填写"归入其中。

## 5. 列表渲染（A5）
每条作品卡片按 简介 / 特点 / 二创内容 / 打包源码 四行渲染；缺段用占位提示（兼容老作品）。时间倒序不变。

## 6. 兼容与失败处理
- 老作品（v6.4/6.5.0 单段）：`parseNote` 回退，四段里"特点/二创内容"显示"（旧版作品未填写）"。
- 包体上传失败：进断网队列（沿用 `publishOrQueue`），Issue 里"打包源码"段标注"包体待重传"，联网后补传。
- 密钥扫描：发布端 + 安装端双扫，沿用 v6.5.0。

## 7. 验证口径
- Node 回归：四段 schema 编解码、兼容回退、唯一区域常量、表单校验。
- 浏览器自测：真页面发布向导字段齐全、列表四段渲染、零报错。
- GitHub 实地：造一件四段式作品上传，API 读回核验四段标记 + 包体目录唯一。
- 既有回归不破坏：v6.5.0/6.4.0/楼层快照全绿。
