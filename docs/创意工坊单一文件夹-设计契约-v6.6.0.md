# 云境 · 创意工坊单一文件夹 —— 设计契约（v6.6.0）

## 1. 目标与不变边界

- 目标：把二创从"元数据在 Issues、包体在 packages/ 两处分散"改为**仓库内唯一一个总文件夹** community/works/，玩家在云境内一站式浏览/下载/安装/发布，像创意工坊。
- 不变：零后端静态 PWA；主程序归开发者；开发者不审核不担责；token 永不入包；原著设定与数值规则不因二创改动。

## 2. 数据布局（唯一区域）

```
community/
  README.md                         ← 区域规约（唯一入口说明）
  works/                            ← 唯一作品根
    catalog.json                    ← 清单：数组，按 createdAt 倒序；每项含 slug/title/author/createdAt/summary/size/hash
    <时间戳>-<slug>/                 ← 每件作品一个子文件夹，名带时间戳天然按时间排
      README.md                     ← 四段式正文（简介/特点/二创内容/打包源码），玩家可读
      meta.json                     ← 机器元数据：title/author/createdAt/baseVersion/package/size/hash
      package.zip                   ← 真二进制 zip 增量补丁包（manifest.json + content/*.json）
```

- 唯一性硬约束：`PACKAGE_ROOT = 'community/works'` 写死在 github-client；不再有第二写入函数、不再写 community/packages/、不再用 Gist。
- 兼容：`community/packages/` 与 `二创投稿` Issues 为**历史只读**，自 v6.6.0 起不写入；不删除（遵守"不许删除"）。

## 3. 读写API（github-client.js）

- `listWorks()`：GET contents/community/works → 读 catalog.json（多线路+超时）；返回 `{ok, items}`，items 按 createdAt 倒序。附带本机缓存 `yj_works_cache`。
- `readWorkFile(slug, file)`：GET works/<slug>/<file>（README.md/meta.json），返回文本。
- `getPackageUrl(slug)`：返回 package.zip 的 raw/下载 URL（供云境内 fetch）。
- `publishWork(slug, files[])`：把一件作品的 README.md/meta.json/package.zip 用 contents API PUT 到 works/<slug>/（存在带 sha 覆盖），再更新 catalog.json（读旧→追加→写回，带 sha）。
  - 并发覆盖保护：catalog 写回用 sha CAS；冲突返回明确错误，提示重发，不静默丢。
  - token 只从本机读，不进任何 body 字段。

## 4. 云境内体验（creation-hub.js）

- 浏览：`renderList()` 数据源改为 `GC.listWorks()`（不再是 listFanworks Issues）。每条展示：标题、作者、时间、四段式摘要（从 README.md 解析，四段标记沿用 v6.5.1）、作品文件夹路径。
- 一键下载安装：每条有"⚙ 一键下载安装"按钮 → `openInstall({rawUrl: getPackageUrl(slug)}, meta)`，复用现有 解包→三方合并→备份→应用→回滚 全流程，不跳 GitHub 网页。
- 发布：向导产出四段式 README + meta.json + package.zip，调用 `GC.publishWork()`，全程在云境内；成功后刷新清单。
- 断网：浏览读本机缓存并提示"离线·显示上次缓存"；发布入队 `publishOrQueue` 的 works 版本，联网补发。

## 5. 四段式正文（沿用 v6.5.1 schema）

README.md 用 `<!--YJ_V2-->` 包裹四段：简介/特点/二创内容/打包源码。打包源码段写明作品文件夹路径、包文件名、sha256、文件清单，并明示"内容层明文，非云境主程序 .js"。

## 6. CI 修复（A）

- 根因：历次升版本只改 YJ_VER，未跑 `scripts/sync-version.mjs`，导致 43 处不同源（CI 第②闸）+ index.html YJ_VER 停在 6.3.6（第④/⑤闸）+ changelog 当前版本条目停在 v5.1.0。
- 修法：`node scripts/sync-version.mjs` 同步全站锚点（该脚本只改"当前版本"锚点、不碰历史版本号，安全）；人工补 changelog 当前版本条目（脚本明确不代写）。
- 验证：本地 ②④⑤ 转绿；推送后远端 CI run 转 success（API 实地核验）。

## 7. 版本与挂载

- 版本 6.5.1 → 6.6.0；studio.html / sw.js 挂载与预缓存含 github-client.js、creation-hub.js、zip-writer.js、patch-engine.js、content-adapters.js。
- 用 `sync-version.mjs` 统一升版本，避免再次欠债。

## 8. 失效条件

- 若 GitHub 改变 contents API 语义或目录读取限额，重写第 3 节。
- 若用户引入后端/自有对象存储，可去掉 token 与限流边界，重写第 3/4 节。
- 若用户改主意要多个板块，推翻"唯一区域"约束，重写第 2 节。

## 9. 验证清单

- Node：`v660-works-schema` 纯函数（清单排序/四段/README 解析/路径唯一）。
- 浏览器：`v660-browser-check` 挂载、全局对象、零报错、works 数据源。
- 真机：造一件作品写入 works/<时间戳>/，清单更新，README+zip 同处；云境内一键下载安装到新档不坏档；CI 远端转绿。
- 回归：既有全套（v651/v650/v65/floor-state/v640）不破坏。
