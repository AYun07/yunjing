# 云境 · 二创版块设计契约 v6.4.0

## 0. 一句话目标
在不改变"云境主线完全由开发者掌控"的前提下，于同一 GitHub 仓库内开一个**二创版块**，玩家可自行上传/下载二创作品，按时间排列，开发者不参与内容与审核，仅提供场所与安全提醒。

## 1. 用户原话拆解（验收源）
1. 云境主线还是我的，照常更新，我完全掌控。
2. 云境项目里单独开一个二创版块，供玩家上传下载二创资源。
3. 我全程不参与任何操作（不审核、不合并、不管理内容）。
4. 玩家在自己云境里确认上传后，自动打包并上传到统一位置。
5. 二创资源按时间排列。
6. 上传前弹窗确认：开源、无盈利、注明与主线区别/更新内容。
7. 版块内提醒玩家当心病毒等安全风险。
8. 国内连 GitHub 总断，必须做好网络容错。
9. 存档云同步为锦上添花（本版先做基础设施，不作为必须交付）。
10. 回档时"足迹/传承是否随回档退"由玩家自己勾。

## 2. 三条不可违背的物理/既定事实（决定方案）
| 事实 | 依据 | 应对 |
|---|---|---|
| 网页 JS 读不到自身目录的其它源码文件（浏览器沙箱），手机尤甚；`showDirectoryPicker` 仅桌面 Chrome/Edge | Web 平台安全模型；file-bridge.js:42 已检测该 API | 默认打"增量包"：打包浏览器内部（localStorage/IDB/内存）的玩家二创内容，全平台可行。完整源码包仅桌面授权后可选，手机禁用并说明 |
| 零后端（DR-001），云境无自建服务器 | DECISIONS.md DR-001 | 统一位置用 GitHub 仓库 Issues（公开、天然按时间、玩家自发、无需开发者合并）+ 玩家自己的 Gist 存大包 |
| GitHub Issues API 不支持上传二进制附件 | GitHub API 限制 | 包体 gzip+base64 存玩家自己的公开 Gist，Issue 正文放说明 + Gist 链接；下载端还原 |

## 3. 方案定案（负责人拍板，不再征求技术意见）
- **版块载体**：`AYun07/yunjing` 仓库 Issues，标签 `二创投稿`。天然满足"统一位置 / 按时间排列 / 全公开 / 我不参与 / 玩家自发"。仓库内 `community/README.md` 作静态版块说明与安全提醒。
- **二创包**：默认"增量包"= manifest.json + 玩家可持久化二创内容（新模块/DLC/设定/正则/预设/世界书/存档），gzip 后 base64 存 Gist。桌面授权后可附加完整源码（可选，手机禁用）。
- **发布流程**：填说明（与主线区别/更新内容）→ 强制确认弹窗（开源无盈利 / 不含密钥隐私 / 风险自负 / 已注明区别）→ 打包 → 建 Gist → 发 Issue（带标签）→ 完成。
- **浏览下载**：云境内"二创版块"面板 fetch Issues（按 created_at 倒序），显示作者/说明/时间/下载；顶部固定安全提醒。
- **网络容错**：多线路（api.github.com + 多个 ghproxy 镜像）、指数退避重试、断网本地队列（联网自动补发）；明确披露国内无法 100% 保证。
- **回档自选**：快照新增 `persist` 字段单独记录足迹/传承，rewindTo 按 opts.includePersistent 决定是否还原，默认否。

## 4. 模块划分
| 文件 | 职责 |
|---|---|

| `js/github-client.js` | GitHub REST 多线路客户端：Gist 创建、Issues 列表/创建、token 本地管理、重试、离线队列 |
| `js/creation-hub.js` | 二创版块面板：浏览/排序/下载/安全提醒 + 发布向导（确认弹窗/打包/上传） |

## 5. 验收句
1. 断网/无源码授权环境下，玩家可把自己改的二创内容打包成合法 zip（CRC 校验通过）、含 manifest。
2. 发布前强制确认弹窗，四项声明必须全勾才能继续；取消则不留任何上传。
3. token 只存本地，任何上传包/issue body/manifest 均不含 token 与 API 密钥（自动扫描断言）。
4. 版块列表按时间倒序，每条有作者/说明/时间；顶部安全提醒常驻。
5. 回档面板勾选"连足迹/传承一起退"时该类数据随楼层还原，不勾则保持；逐字段测试。
6. 既有回归（楼层快照 503、比对 32、E2E）不破坏；内存有界压测仍通过。
7. 网络容错：主线路失败能切备用线路；断网发布进队列，恢复后补发。

## 6. 未验证项 / 边界（强制披露）
- GitHub API 国内连通性无法在沙箱内代表玩家真实网络；只能保证代码有多线路与重试，无法保证"永不断"。
- 玩家需自有 GitHub 账号与 token（低权限 fine-grained 即可）；无账号者无法发布（可浏览/下载）。
- 完整源码包手机端不支持（物理限制），只支持增量包；桌面授权后可附加完整源码。
- 开发者"不参与"= 不审核不合并；但仓库与 Issues 的初始化配置（建仓库、建标签、写 README）为一次性搭建，由本项目完成时建立。
- 内容合规依赖玩家自律声明 + GitHub 举报机制，云境不做内容审核（符合"我不参与"）。
