# 全量楼层快照与回档 · 设计契约（v6.3.14）

> 状态：已回读确认范围（用户拒绝选项后按"最贴合原话"假设推进，见文末假设）。
> 本文件是实现的唯一依据。改实现前先对这里；对不齐先补契约，不带病推进。

## 0 · 病因与目标（为什么做）

- 一份 1.7GB 存档确诊：`backups[].payload` 174 份全量 gzip 快照无限追加（占 94%），加载时 `JSON.parse` 峰值冲 10GB。**根因是"全量快照 × 无限追加"**。
- 云境现状：主档 `.bak` 固定 1 份、`turnArc` 按 index 去重覆盖 —— **膨胀风险已受控**，但**回档只还原 4 类数据**（vars/digest/drift/histLen），其余随档数据回档后"停在未来"，导致多次回档后剧情对不上。
- 目标：①存档体积 ≈ 真实数据体积（放大 ≤3 倍，绝不出现 400 倍）；②任意楼层可回档；③所有随剧情演化的数据同步到该楼层；④回档可撤销。

## 2 · 数据结构（差量 + 锚点，体积有界）

IDB 新增一个键，固定覆盖式（不是无限追加）：
- 键：`floorState/<saveKey>`
- 值：`{ v:1, base: <全量基线>, deltas: { [index]: <差量> }, anchors: { [index]: <全量> }, tip: <最新index> }`

- **基线 `base`**：第 0 层开始前的全量状态（所有 1.1 字段的值）。
- **差量 `deltas[i]`**：第 i 层相对 i-1 层**变化了的字段**（顶层键对比 JSON 串，只存不同者）。对话正文用 `histLen` 数字代替。
- **锚点 `anchors[i]`**：每 `ANCHOR_EVERY=20` 层存一份全量，限制重放长度。
- 回档到第 K 层：`anchor = 小于等于 K 的最大锚点`；从 anchor 的全量出发，依次应用 `anchor+1..K` 的差量，重建该层全量状态。

体积账（保守估算）：单差量 ≈ 0.5–3KB（只变几个字段+histLen），单锚点 ≈ 20–80KB（含旁路键快照）。
- 1000 层：50 锚点 × 80KB ≈ 4MB + 1000 差量 × 3KB ≈ 3MB ≈ **7MB**。
- 1 万层：≈ 40MB + 30MB ≈ **70MB**（对话正文另走 transcript，不在此账内）。
- **放大倍数口径**：快照总量 ÷ 真实状态变化量 ≤ 3。若超，先查是不是误把对话正文/图片塞进快照。

## 3 · 回档算法（rewindTo 升级）

1. 等 `floorState` 写队列排空（防并发复活）。
2. 重建目标层 K 全量状态（§2 锚点重放）。
3. 应用：storyState 各字段整体还原；旁路键用 `localStorage.setItem` 逐键写回。
4. 对话历史按 `histLen` 截断（只缩不扩）；transcript 按 histLen 截断。
5. DOM 卡片按 `data-turn >= cutIndex` 删除。
6. `turns` 热栈、旧 `turnArc` 同步裁剪，防刷新复活。
7. 保存后返回；时光轴负责 replay 重挂。
8. **可撤销**：回档前把"当前全量状态 + 当前 conversationHistory 长度"压入恢复点栈（IDB，上限 5 个，覆盖式），加"撤销上次回档"入口。

## 4 · 兼容与降级

- 老存档无 `floorState`：首次保存时以当前状态建 `base`，之后正常记差量；回档降级为现有 `turnArc` 40 轮热栈（行为不变）。
- StorageBoost 不可用：整个楼层快照功能静默跳过，回档退回现有机制，不阻断创作。

## 6 · 假设（用户未选，按原话推进，可随时推翻）

- A 数据范围：全量（§1.1 全部纳入），全局持久项（§1.2）排除。
- B 回档安全：可撤销，恢复点上限 5。
- C 楼层粒度：1 楼层 = 1 对话轮次（用户指令 + AI 正文），与时光轴一致。
- D 体积口径：改用"放大倍数 ≤3"，原"1万轮≤50MB"绝对值不成立（正文本身巨大）。
