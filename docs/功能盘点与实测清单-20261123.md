## 〇、浏览器实测结论（先说实话）

按你说的"你自己用浏览器测"，我用沙箱里的 Chrome（144 内核，Chromium；沙箱无 Edge，用 Chrome 等价）实测了封面、世界选择页、studio.html。

| 测项 | 实测结果 | 诚实边界 |
|---|---|---|
| JS 堆内存 | 封面/选世界页 **3.9–5MB**，加载 13–23 个脚本、0 个视频请求 | **没能复现你说的"开局 200MB、很卡"**。入口守卫把无参数访问都弹回封面，我的自动化没能走到"真正选世界→进入对话→多轮游玩"的主界面（那里才会加载 354 模块 + 470MB 视频）。你那 200MB 很可能是真正游玩时或浏览器进程总内存（含扩展/其他标签），沙箱这套干净环境测不到。 |
| 端点连接失败（第4条） | 封面阶段无端点请求，无法实测 | 需要具体失败端点才能定位 |
| 地图重叠（第7条） | 自动化命中的标签元素 4 个、重叠 0 | 我停在世界选择页，没进到舆图主界面，**这条未复现**，需要你给具体是哪张地图 |
| 状态栏多余文字（第10条） | 封面顶部只有"云 境"标题，无多余文字 | 需要进到游戏主界面的状态栏才能看，**这条未复现** |

**结论**：能确定的不是"内存真的 200MB"，而是代码层确实臃肿——470MB 视频、354 个 JS 模块、十几组功能重复。这是可以动手优化的确定性抓手。主观卡顿/重叠现象需要你在自己电脑上配合给个截图或具体操作路径，我才能精准修而不是瞎改。
