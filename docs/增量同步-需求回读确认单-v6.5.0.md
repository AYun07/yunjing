# 云境 · 增量同步 需求回读确认单 v6.5.0

> 用大白话把"你到底要什么"念一遍。看哪句说歪了，直接指出，我改完再往下走。

## 一、你这句话拆成大白话，我理解是这样

1. **别再整个打包了**。以前发布二创是把你改过的东西整个塞一个包。现在要改成：先拿当前最新版云境当"原版底子"，只把**被改动过的那些地方**挑出来打包。没动的一律不传。
2. **下载的人要能自动装上**。别人下载后，工具自动备份他原来的，再把新东西覆盖上去，出问题能一键退回去。
3. **防止版本对不上**。每个人手里的云境版本可能不一样，所以装之前要先检查：一样就直接同步，本地也改过同一处就合并，改不动的就明确提示，绝不闷头乱覆盖。
4. **什么都不挑类型**。DLC、插件、小云做的工具、存档、预设、世界书、世界、新内容、资源包、图片、视频、各种文件——都能上传、下载、打包。
5. **主线还是你的**。这些只在二创版块里流转，不碰云境主程序，开发者不参与内容。

## 二、有一条物理边界，我必须说实话（不然又变成空话）

你说的是"**检测最新版云境，找出哪里改了**"。这里有个绕不开的事实：

> **浏览器里的网页，读不到你电脑上/手机里的云境源码文件本身。**（这是浏览器的安全规定，不是我偷懒。）玩家在"小云工坊"里改东西，实际改的是浏览器内部存的**内容数据**（DLC设定、预设、世界书、正则、存档这些），不是磁盘上的 `.js` 源码文件。

所以"找出改了哪里"分两种，我都做，但能力不一样：

| 轨道 | 能比对什么 | 哪些设备能用 | 说明 |
|---|---|---|---|
| **默认轨（内容级 diff）** | 玩家改过的内容数据键：新增/修改/删除 | **所有设备**：手机、平板、电脑都能用 | 这是主力。你要的 DLC/预设/世界书/存档/图片等，绝大多数都在这条轨上，能真正做到"只传改动" |
| **可选轨（源码级 diff）** | 真正的 `.js/.html/.css` 源码文件 | **仅桌面 Chrome/Edge**，且要你手动授权项目文件夹 | 手机做不到（浏览器不给权限）。授权后能像 git 那样对比源码文件，只传改动的文件 |

我不会假装手机能改源码——那样做出来你一用就穿帮。

## 三、还有两条实话，先说在前头

- **存档能打包，但默认要拆掉密钥**。很多人存档里存着 API Key。默认会把 `sk-`、`ghp_` 这类密钥字段自动剔除再打包；你要是坚持连密钥一起传，得手动勾"我确认包含密钥"，且只走你自己的私密 Gist。**绝不会因为打包把你的密钥泄露到公开 Issue。**
- **超大文件有上限**。GitHub 免费 Gist 单文件约 100MB。视频、大资源包超过这个数就传不上去。做法：超限时自动切成多片分卷打包，并在列表里明确标注"分卷 N 片"；实在超过总分卷上限的，提示改用网盘链接（二创帖正文允许贴链接）。不会静默失败。

## 四、验收句（怎样算做对了）

| # | 验收句 | 怎么验 |
|---|---|---|
| A1 | 发布时只打包"改动项"，未改动的内容不进包 | 造 1 改 3 不改的内容，包内 manifest 只列 1 项改动 |
| A2 | 包能被解包还原，字节级一致（CRC 通过） | 打包→解包→逐字节比对 |
| A3 | 下载前先做版本一致性检查，给出"同步/覆盖/合并/冲突"分类清单 | 构造 base/ours/theirs 三方，四类都能判对 |
| A4 | 三方合并：本地没改→直接用新的；两边都改不同处→合并；都改同一处→标冲突让人选 | 三组用例逐条断言 |
| A5 | 安装前自动备份，装完能一键回滚到安装前 | 安装前后快照比对，回滚后字节还原 |
| A6 | 全类型覆盖清单逐类可打包：DLC/插件/工具/存档/预设/世界书/世界/新内容/资源包/图片/视频/文件 | 每类造一个样本，全部进包 |
| A7 | 密钥默认剔除；超 100MB 自动分卷并标注 | 塞一个假 key 断言被剔除；塞一个 120MB 样本断言分成 2 卷 |
| A8 | 桌面授权后可选源码级 diff，只打改动文件 | 授权临时目录，改 1 个文件，包内只出现该文件 |
| A9 | 全程不碰主线、token 不进包、既有回归不破坏 | token 扫描 + 既有 503/32/E2E 回归全绿 |

## 五、三档排期（不报单一数字）

| 档 | 工期 | 前提 |
|---|---|---|
| 乐观 | 1 个工作日 | 内容级 diff + 三方合并 + 备份回滚一次过，无返工 |
| 正常 | 1.5 个工作日 | 加上解包/分卷/全类型适配 + 浏览器实测调一轮 |
| 悲观 | 2.5 个工作日 | 桌面源码级 diff 权限在不同浏览器表现不一，需额外适配 + GitHub 推送遇 422 重试 |

**最可能返工的三处**：① 三方合并的冲突判定（都改同一处时的口径）；② IndexedDB 里大内容的枚举与还原时序；③ GitHub 大包推送分片在弱网下的重试。

## 六、未验证项（强制披露）

- GitHub API 国内连通性无法在沙箱代表玩家真实网络；代码有多线路+重试，但不保证"永不断"。
- 源码级 diff 只在桌面 Chrome/Edge 可用，且依赖用户手动授权项目文件夹；Safari / 手机浏览器无法提供。
- 单文件 >100MB 需分卷，分卷上限内的下载完整性依赖玩家网络；超过总分卷上限的内容只能走网盘链接。
- 全类型的"能打包"指能被扫描枚举到的内容键；极少数只存在内存、不落盘、也不提供导出接口的临时数据，无法纳入（会明确列出哪些没纳入）。
