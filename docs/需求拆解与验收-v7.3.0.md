## 4. 技术决策记录

### DR-007 模型配置单点收敛
- 背景：全站 4+ 配置入口并存，用户明确要"有且仅有天地设置一处"。
- 候选：①全部合并进 settings.html，删弹窗；②保留弹窗但只留一个入口按钮；③保留弹窗作为 settings 的浮层实现。
- 取舍：选①（按假设 A1）。否掉②③，因为用户明说"不要再另设界面和弹窗"。
- 后果：配置集中、维护点单一；代价是左栏/引导的便捷入口消失，需在 settings 内做清晰分区补偿。
- 失效条件：若真机实测发现某流程（首次启动引导）必须弹窗引导配置，重新评估。

### DR-008 云境作为卡在酒馆使用
- 背景：用户取消"角色卡"功能，改为云境本身随时可作为卡在酒馆用；已有 `yunqi-latest.json`。
- 候选：①完善已有云起卡并加导出入口；②重写一套新卡格式；③只出文档说明手动用法。
- 取舍：选①（按假设 A4），复用已验证的 V2 卡结构。否掉②因为重复造轮子、③不满足"随时可作为卡"。
- 后果：兼容现有生态；代价是卡内容需与云境版本同步维护。
- 失效条件：若 SillyTavern 卡格式升级或用户指定别的平台，重新评估。
