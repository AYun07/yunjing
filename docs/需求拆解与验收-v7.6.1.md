# 需求拆解与验收 · v7.6.1（更新死循环修复）

## 一、需求原话与卡点

> 「更新安装完后显示的还是旧版本，并且再次提醒更新，更新完后还是旧版本并再次提醒更新」

卡点：**更新流程形成死循环**——装完版本不变、提示不消失，反复装反复提示。

## 二、四问

| 问 | 答案 |
|---|---|
| 现象是什么 | 更新装完版本号仍显示旧版；再次检查又提示有新版本；再装仍旧，循环 |
| 哪一层出问题 | 桌面客户端外壳（app.asar）的版本判定与显示，不是内容层、不是站点 |
| 为什么反复 | 版本判断条件恒成立，装包没改变判断条件 |
| 怎样算修好 | 装一次新包后：版本号显示正确、不再提示更新、不再循环；后续恢复免重装 |

## 三、根因（决定性证据）

本地源码各处版本均为 `7.6.0`；但已发布且用户实际运行的 `app.asar` 内 `package.json.version = 7.3.0`（setup.exe 长期复用固定外壳）。

- `main.js` 的 `VERSION = require('./package.json').version` → 用户手上恒为 `7.3.0`。
- `checkForUpdate()`：`hasUpdate = compareVer(远端 7.6.x, VERSION 7.3.0) > 0` → **恒为真**。
- "当前版本"显示读同一个 `VERSION` → **装完仍是 7.3.0**。
- 内容热更新只写 `userData/yj-content`，改不到 `app.asar` → 存量用户靠内容更新无法自救。

这是 DR-104 的镜像问题：DR-104 是"壳旧 + Release 缺包 → 恒判最新"，本次是"壳旧 → 恒判有更新"。

## 四、验收句（可验证口径）

| 编号 | 验收句 | 验证方式 |
|---|---|---|
| A1 | 有效版本取外壳版本与内容版本的较大值 | 单元测试：壳 7.3.0/内容 7.6.0 → 有效版本 7.6.0 |
| A2 | 当内容已到最新版时 `hasUpdate` 为假 | 单元测试：远端 7.6.1、有效版本 7.6.1 → hasUpdate=false |
| A3 | 显示的"当前版本"反映有效版本而非固化外壳 | 检查 `client-info.version` 返回有效版本、保留 `shellVersion` |
| A4 | 新包外壳版本同步为 7.6.1 | 产物校验：解包 app.asar 读 package.json=7.6.1 |
| A5 | 修复代码随包送达 | 产物校验：app.asar 内 main.js 含 effectiveVersion，模块可真实加载 |
| A6 | zip 与 dist 外壳字节一致 | SHA 比对 |
| A7 | 更新元数据三处一致 | update-latest / Release 资产 / 本地文件 SHA 一致 |
| A8 | 存量用户一次更新后不再提示 | 逻辑推演 + 场景模拟：装完有效版本=max(7.6.1,内容)=远端 → hasUpdate=false |

## 五、修复方案

1. **代码层（治判断/显示）**：`main.js` 新增 `effectiveVersion() = max(壳版本, 内容版本)`；hasUpdate 判断、当前版本显示、发现新版提示、关于框、`client-info.version` 全部改用有效版本；`client-info` 新增 `shellVersion` 供诊断（向后兼容）。
2. **打包层（治送达）**：修复在 app.asar 内、内容热更新改不到——重打带修复且 package.json=7.6.1 的 app.asar 与 win-unpacked.zip，经默认 A/B 更新通道送达存量用户。
3. **元数据层（治触发）**：升 v7.6.1（须高于存量外壳 7.3.0 才触发更新判断），update-latest.json 资产名/版本/双 SHA 同步。

## 六、检查点报告

### 检查点 #10（v7.6.1）

- **做完什么**：根因定位到外壳版本固化；代码层引入有效版本并替换全部判断/显示点；全站版本升 7.6.1；文档（README/VERSIONS/changelog/release-notes/DECISIONS）口径更新；决策记录 DR-117。
- **试过什么**：语法检查、场景单元测试、产物级 asar 解包校验、zip/dist SHA 比对、回归测试。
- **还差什么**：Windows 真机 GUI 双击 exe 的菜单点击（沙箱无 GUI，以 mock electron 通道断言替代）。
- **卡在哪**：无阻塞。NSIS 无法在本环境编译，setup.exe 复用固定外壳——但默认更新走 zip 的 A/B 通道，修复可送达；setup 作为降级路径的旧外壳问题，随用户走默认路径被覆盖，如实披露为未上真机项。
